**Issue.** #12

## Que se hizo

Se levanto el visor con React 18, Vite y Leaflet, y se dibujaron los ocho
distritos del canton de Tilaran sobre una capa base de OpenStreetMap, con zoom,
desplazamiento, tooltip al pasar el cursor y un panel con la ficha del distrito
seleccionado.

La estructura separa una sola responsabilidad por archivo:

| Archivo | Responsabilidad |
|---|---|
| `src/datos/cliente.js` | Unico modulo que sabe de donde vienen los datos |
| `src/componentes/MapaCanton.jsx` | Mapa, capa base, poligonos, encuadre |
| `src/componentes/PanelDistrito.jsx` | Ficha del distrito seleccionado |
| `src/componentes/AvisoModoSimulado.jsx` | Banda de aviso exigida por el contrato |
| `src/estilos/tokens.css` | Sistema de diseno, evidencia H5.1-sistema-diseno |

### Tres decisiones de diseno

**1. El origen de los datos esta aislado en un solo modulo.**
La API no existe todavia: segun el roadmap llega en la semana 6. El visor lee los
archivos estaticos que genera `frontend/herramientas/exportar_simulados.py` a
partir de `contratos/simulados`. Estan en `public/` y se consumen con `fetch`, no
se importan como modulo, precisamente para que migrar a la API real sea cambiar
una URL en `cliente.js` y nada mas.

**2. El encuadre se calcula, no se escribe.**
El mapa se ajusta a los limites de la geometria que recibe, en lugar de fijar
coordenadas de Tilaran en el codigo. Las geometrias actuales son marcadores de
posicion y se reemplazan por los limites reales del SNIT cuando la API sirva los
datos de H1.3. Con coordenadas fijas, ese dia el mapa apuntaria al lugar
equivocado sin que nadie entendiera por que.

**3. Todos los distritos se dibujan con la trama de ausencia de dato.**
No hay modelo entrenado, asi que ningun distrito tiene nivel de riesgo. Pintarlos
con un color de la rampa afirmaria un riesgo que nadie calculo. El panel lo dice
explicitamente: "No es un riesgo bajo: es la ausencia de una medicion."

La banda permanente de modo simulado no es una decision propia: la exige el
contrato, `contratos/enums.py` linea 55 y `contratos/esquemas.py` linea 208.

## Como se verifico

Cuatro comprobaciones, tres automaticas y una visual.

    python -m contratos.verificar
    python frontend/herramientas/exportar_simulados.py
    npm run lint
    npm run build

Y la verificacion visual, levantando el visor y usandolo:

    npm run dev -- --port 5180

Se comprobaron cuatro comportamientos en el navegador:

1. El mapa abre encuadrado sobre los ocho distritos
2. Zoom con la rueda y con los controles, y desplazamiento arrastrando
3. Clic en un distrito: se marca con borde continuo negro y se llena el panel
4. Navegacion por teclado: la tecla Tab enfoca los distritos uno a uno

## Observaciones

**Un defecto que ninguna verificacion automatica detecto.** En la primera
revision visual, el mapa abria mostrando media Costa Rica en lugar del canton. El
linter estaba limpio y las pruebas de contrato pasaban.

La causa: el ajuste de encuadre corria antes de que el navegador terminara de
calcular el tamano del contenedor, asi que Leaflet medía una caja mas chica que
la final y elegia un zoom demasiado abierto.

El primer intento de arreglo, esperar un cuadro de render, no alcanzo: la rejilla
de CSS resuelve el alto despues. La solucion definitiva fue observar el
contenedor con `ResizeObserver` y reajustar cada vez que cambia de tamano de
verdad.

Es el segundo defecto de esta historia que aparecio mirando la pantalla y no
leyendo el codigo. Vale registrarlo como argumento concreto de por que "verificar
ejecutando" significa abrir la pantalla, no solo correr el script. El otro esta
documentado en `H5.1-sistema-diseno.md`: texto ilegible sobre la trama diagonal.

**Limitaciones conocidas.**

- Las geometrias son cuadrados de marcador de posicion, no los limites reales de
  los distritos. Los reales ya existen en la base desde H1.3, pero llegan al
  visor cuando exista la API. Hasta entonces la banda de modo simulado se
  mantiene visible de forma permanente.
- La capa base depende de los servidores de OpenStreetMap. Sin conexion, los
  poligonos se dibujan igual pero sin contexto geografico.
- El aviso de modo simulado se muestra en pantalla pero todavia no se anuncia a
  lectores de pantalla mas alla del `role="status"`. Se revisa en H5.2.
