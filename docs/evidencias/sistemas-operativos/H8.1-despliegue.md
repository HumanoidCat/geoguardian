# Evidencia · H8.1 · Despliegue reproducible con Docker Compose

**Fecha.** 2026-08-03
**Responsable.** Alejandro Josue Rodriguez Zamora
**Materia y criterio.** Sistemas Operativos · SO-1, elemento *virtualizacion*

## Que se hizo

Se definio el entorno de la base de datos en `docker-compose.yml` usando la
imagen `postgis/postgis:16-3.4`, con:

- volumen nombrado `geoguardian_datos_db` para persistencia entre reinicios
- healthcheck con `pg_isready`, intervalo de 10 s y periodo de gracia de 30 s
- variables leidas desde `.env`, que no se versiona
- fallo explicito si `POSTGRES_PASSWORD` esta vacia, en vez de arrancar con un
  valor por defecto
- script de inicializacion que habilita PostGIS, `postgis_raster` y
  `pg_stat_statements`, y crea los cuatro esquemas del modelo

## Como se verifico

Maquina limpia: Windows 11, Docker Desktop 4.85.0, motor 29.6.2 sobre WSL2.

```
docker compose down -v
docker compose up -d
docker compose ps
docker compose exec db psql -U geoguardian -d geoguardian -c "\dn"
```

## Analisis desde Sistemas Operativos

**Virtualizacion.** El contenedor no es una maquina virtual: comparte el nucleo
del anfitrion y se aisla mediante espacios de nombres y grupos de control. Por
eso arranca en menos de un segundo, frente a la decena larga de segundos que
tarda una VM. En Windows el nucleo compartido lo aporta WSL2, no el sistema
anfitrion directamente.

**Aislamiento de red.** Compose crea la red `geoguardian_default`. Los servicios
se resuelven entre si por nombre de servicio (`db`), no por direccion IP. Desde
el anfitrion se llega por `localhost:5432` gracias a la publicacion del puerto.
Esa es la razon de que `.env` use `POSTGRES_HOST=db`: ese nombre solo existe
dentro de la red del contenedor.

**Persistencia.** El volumen nombrado sobrevive a `docker compose down`, pero no
a `down -v`. La distincion importa: el segundo borra los datos sin confirmacion.

**Memoria compartida.** Se asignaron 256 MB a `/dev/shm`. PostgreSQL los usa para
consultas con ordenamientos o uniones grandes; el valor por defecto de Docker
(64 MB) provoca errores en consultas espaciales pesadas.

## Incidencia asociada

La primera version del archivo pasaba `--locale=es_ES.UTF-8` a `initdb`. Esa
configuracion regional no viene generada en la imagen base, `initdb` fallaba y el
contenedor entraba en bucle de reinicio. Se corrigio usando el proveedor ICU, que
no depende de las configuraciones regionales del sistema operativo. Ver I-02 en
`docs/04-bitacora-incidencias.md`.
