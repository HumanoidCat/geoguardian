## CA-1 · El entorno se deriva, y se probo en las dos direcciones

**Es el unico criterio que se puede poner en verde sin hacer nada**, escribiendo
una constante. Por eso su comprobacion es el cambio, no el valor.

| Estado de la API | Caja del entorno | Pastilla de la cabecera |
|---|---|---|
| **Caida** (502 en `/api/salud`) | **«Respaldo estatico»** — «La API no respondio y el visor cayo al respaldo. Lo que se ve no viene de la base de datos.» | `respaldo estatico` |
| **Levantada** (`uvicorn ... --port 8000`) | **«Local»** — «El visor habla con una API que corre en esta maquina.» | `API` |

Las dos lecturas salen de `salud.origen` y de `window.location.hostname`.
**Ninguna constante decide el texto**: si la hubiera, las dos filas dirian lo
mismo.

Capturas: `H12.2-monitoreo/monitoreo-respaldo.png` con la API caida, y
`H12.2-monitoreo/monitoreo-1280-real.png` con la API levantada.

## CA-2 · Los cinco campos, con su lectura

Medido con la API levantada y **sin base de datos**, que es el caso que mas cuesta
leer bien: la API responde, pero sirve el repositorio de relleno.

| Campo | Valor | Esperado | Que dice la pantalla |
|---|---|---|---|
| `modo` | `simulado` | `real` | «La API no llego a PostgreSQL y esta sirviendo el repositorio de relleno. No hay variable que forzar: hay una conexion que arreglar.» |
| `base_datos_conectada` | `false` | `false, con modo simulado` | «Coherente con modo simulado.» |
| `ultima_ingesta` | _sin dato_ | una fecha de menos de 48 h | «Nunca se ejecuto la ingesta, o la API no pudo leerlo. No se muestra una fecha en su lugar.» |
| `version_contratos` | `1.4.0` | `1.4.0` | «Coincide con el arbol construido (1.4.0).» |
| `version_api` | `0.1.0` | acompana a la de contratos | «Sirve para saber que arbol esta desplegado, junto con la de contratos.» |

**Caso negativo cumplido:** con `modo: simulado` el texto explica que la API no
llego a PostgreSQL. No dice solamente «simulado».

### Un defecto que aparecio al mirarlo, y se corrigio

La primera version marcaba `base_datos_conectada` en ambar **aunque su propio
texto dijera «Coherente con modo simulado»**. El color y la frase decian cosas
distintas sobre el mismo campo.

Es una version pequena del defecto que esta pantalla existe para no cometer: un
indicador que se contradice a si mismo. Corregido: lo esperado depende del modo, y
en simulado `false` **es** la respuesta correcta, asi que la fila no se marca.

## CA-3 · La ausencia se declara, no se rellena

`ultima_ingesta` llego `null`. La pantalla muestra **«sin dato»** en cursiva y
explica por que. **No muestra una fecha, ni un guion, ni un cero.** Es **D-07**.

Cuando hay fecha, se muestra con su antiguedad —«hace 3 h», «hace 2 dias»— porque
una fecha sin su antiguedad obliga a hacer la cuenta. Y una fecha futura no se
informa como «hace -2 horas»: se dice que el reloj esta desalineado, que es lo que
de verdad pasa.

## CA-4 · Las versiones, contra el arbol construido

Es la unica comprobacion que acota lo que **D-43** acepta: que el binario
publicado no sea el que el CI construyo y probo.

```
$ python frontend/herramientas/generar_esperado.py
  contratos 1.4.0  <- contratos/__init__.py
  api       0.1.0  <- backend/api/rutas.py
  frontend\public\estado\esperado.json
```

El valor esperado **sale del arbol**, no de una constante en un componente. Ese era
exactamente el defecto de **I-41**, donde `rutas.py` devolvio un valor escrito en
duro durante nueve dias despues de dejar de ser cierto.

Si el archivo falta, la pantalla **lo dice** en vez de suponer que todo coincide.

## CA-5 · Lo que la pantalla NO vigila, dicho en la pantalla

No hay un recuadro vacio ni un «proximamente». Hay dos huecos nombrados, con su
causa y de que depende cerrarlos:

- **Las corridas de CI y CD.** La API no expone `control.bitacora_etl`, y pedirselo
  a `api.github.com` desde el navegador seria una peticion a otro dominio, que
  rompe D-23 y el CA-3 de H11.6.
- **El dominio, de forma automatica.** Esta pantalla muestra; no avisa. Las alertas
  de H12.3 escuchan corridas de GitHub Actions, no el dominio: un CI en verde con
  el visor caido no dispara nada.

Y lo dice con su motivo: callarlo la convertiria en lo que este proyecto ya
arreglo tres veces —**I-25, I-39, I-41**—, un indicador que informa sobre si mismo
en vez de sobre el sistema.

**La pantalla no dice «todo bien» en ningun lugar.** Muestra valor y esperado; la
conclusion la saca quien mira.

## CA-6 · Teclado y contraste

**Recorrido con `Tab` dentro del panel.** Con el foco puesto en el titulo «Estado
del sistema», un solo `Tab` lleva a **«Volver al mapa»**, con su recuadro de foco
visible. El siguiente sale de la pagina hacia el navegador.

La lista es corta **porque el panel es una tabla de lectura**: no tiene
formularios, filtros ni controles. Que se recorra en un salto no es un descuido,
es lo que hay. Y el unico control que existe se alcanza sin mouse, que es lo que
el criterio pide.

**Contraste.** El panel **no agrego ningun color**: usa los tokens que ya existian,
asi que `verificar_escala.py` los cubre sin extenderlo. Las cuatro lineas que le
corresponden, de la corrida del 2026-09-17:

```
OK    el foco sobre la superficie                5.75:1   (minimo 3.0)
OK    el texto sobre la superficie              16.10:1   (minimo 4.5)
OK    el texto suave sobre la superficie         6.19:1   (minimo 4.5)
OK    el texto sobre el fondo de aviso          15.16:1   (minimo 4.5)
```

Las cuatro son las que el panel usa: el recuadro de foco de «Volver al mapa», el
texto de la tabla, el texto atenuado de la columna «Esperado», y el ambar de las
filas que piden atencion.

**Salida completa: «Todas las verificaciones pasaron».**

Y una nota del propio verificador que conviene tener a la vista:

```
nota  el texto tenue sobre la superficie da 2.68:1: no sirve para leer
```

`--texto-tenue` **no se usa** en este panel por esa razon. La columna «Esperado»,
que es la mas atenuada, usa `--texto-suave`, que da 6,19:1.

**Ningun estado se distingue solo por color.** La fila que pide atencion lleva
ademas borde izquierdo, y cada valor va con su lectura en texto. **El rojo no se
usa**: esta reservado para riesgo alto en la rampa, y pintar de rojo un campo de
estado lo pondria al mismo nivel visual que un distrito en peligro. Lo que pide
atencion va en ambar, como el resto de los avisos sobre procedencia del dato
(H5.9).

## CA-7 · Sin desbordamiento horizontal

```
document.documentElement.scrollWidth <= window.innerWidth
```

Medido con `scrollWidth - innerWidth`, que dice **por cuanto** se pasa y no solo
si se pasa:

| Ancho | `scrollWidth - innerWidth` | Desborda |
|---|---|---|
| 390 x 844 | **0** | no |
| 768 x 1024 | **0** | no |
| 1280 x 800 | **0** | no |

Capturas de los tres anchos en `H12.2-monitoreo/`, tomadas con
«Capture full size screenshot» para que se vea el panel entero y no solo lo que
entra en la ventana.

A anchos angostos la tabla de cuatro columnas **se desplaza dentro de su propio
contenedor**, no arrastra la pagina. Es lo que el criterio distingue.
