## Lo que estaba mal

### 1 · Los dos diagramas nombraban una ruta que no existe

Decian **`GET /riesgo`**, en singular. La API expone **`/riesgos`**
(`backend/api/rutas.py`) y el visor pide `/riesgos?...` (`cliente.js`). Existe un
`/distritos/{codigo}/riesgo` en singular, pero es otra ruta y no es la del flujo
que el diagrama dibuja.

Quien leyera el diagrama y probara `/riesgo` se comia un 404. Es lo que el propio
README del generador advierte que pasa: *«un diagrama desactualizado es peor que
ninguno: se ve autorizado y dice algo falso»*.

### 2 · La capa de presentacion se habia quedado en agosto

Mostraba «Visor React» y «MapaCanton». Desde entonces entraron el semaforo de
H7.1, el selector de fecha de H5.7 y la ficha con coordenadas de H5.6, y ninguno
aparecia.

### 3 · Dos etiquetas «usa» flotando sin linea

Encontrado al renderizar el diagrama para revisarlo, y **ya estaba en la version
publicada**: dos de las tres etiquetas quedaban sueltas contra el borde derecho
del lienzo, sin ninguna arista que las uniera a nada.

La causa es `splines=ortho`: Graphviz no coloca bien las etiquetas de aristas
ortogonales que cruzan un cluster. Se quitaron las tres palabras en vez de sacar
`ortho` -que reordena el diagrama entero-, porque **la flecha punteada ya
significa dependencia en UML** y la palabra no aportaba nada.

## Lo que se hizo

### El diagrama declara ahora lo que se puede comprobar

`COMPONENTES`, en el generador, asocia cada componente dibujado con **el archivo o
la carpeta que representa**:

| Componente | Ruta real |
|---|---|
| Visor React | `frontend/src/App.jsx` |
| MapaCanton | `frontend/src/componentes/MapaCanton.jsx` |
| TableroSemaforo | `frontend/src/componentes/TableroSemaforo.jsx` |
| PanelDistrito | `frontend/src/componentes/PanelDistrito.jsx` |
| Cliente de datos | `frontend/src/datos/cliente.js` |
| API FastAPI | `backend/api/rutas.py` |
| Repositorio | `contratos/repositorio.py` |
| Contratos | `contratos` |
| Modelado | `backend/modelado` |
| ETL | `backend/etl` |

Y `RUTA_RIESGOS` se escribe **una sola vez**, para que los dos diagramas no puedan
discrepar entre ellos: antes de H6.5 los dos decian `/riesgo` y ninguno existia.

### Dos criterios nuevos, que se agregan y no reemplazan

Los cinco criterios que comprobaban el entidad-relacion **quedan intactos**.

**CA-6 · las rutas que nombran los diagramas existen en la API.** Se leen del SVG
y no del generador: lo que importa es lo que alguien lee en el dibujo, no lo que
el generador pretendia escribir. Se comparan contra las rutas parseadas de
`rutas.py`.

**CA-7 · cada componente dibujado existe en el repositorio**, y en las dos
direcciones:

1. ningun componente declarado apunta a algo que ya se borro,
2. ningun componente declarado falta del SVG,
3. y el control sabe decir que no.

La segunda y la tercera son las que se olvidan. Sin la tercera, esto podria estar
pasando por mirar el lugar equivocado, que es lo mismo que CA-5 evita para el
entidad-relacion.

### El control detecta el defecto que motivo la historia

No alcanza con que pase en verde: **hay que probar que sabe fallar.** Se
reintrodujo el defecto original -`RUTA_RIESGOS = "/riesgo"`-, se regeneraron los
diagramas y se corrio el verificador:

      FALLO  componentes: la ruta /riesgo existe en la API
            rutas.py expone: ['/distritos', '/distritos/{codigo}',
            '/distritos/{codigo}/mediciones', '/distritos/{codigo}/riesgo',
            '/riesgos', '/salud']
      FALLO  secuencia-consulta-riesgo: la ruta /riesgo existe en la API

    2 comprobaciones fallaron
    codigo de salida: 1

Despues se restauro y el verificador volvio a verde. **El defecto que vivio en el
repositorio y en el documento tecnico durante seis dias ahora tarda un CI en
aparecer.**

### Y se miraron

Los dos diagramas se renderizaron a PNG y se abrieron. Asi aparecio el defecto de
las etiquetas flotantes, que ninguna comprobacion habria detectado: es una
propiedad del dibujo, no del contenido. Es **I-10** otra vez —un verificador en
verde dice que no fallo lo que se le pidio comprobar, no que el resultado este
bien—.

## Lo que se corrigio ademas, y no es codigo

El generador y el README de `docs/diagramas/` afirmaban que los otros cinco
diagramas **no se pueden derivar del codigo «con honestidad»**.

La afirmacion era demasiado ancha, y por eso ninguno tenia comprobacion. Lo que no
se deriva son **las capas, las flechas y la degradacion de D-23**: eso es criterio
de quien dibuja. Los **nombres** si.

Las dos frases quedaron corregidas, con el motivo escrito. La distincion no es
academica: mientras no estuvo hecha, los dos diagramas decian una ruta inexistente
y nadie tenia como enterarse.
